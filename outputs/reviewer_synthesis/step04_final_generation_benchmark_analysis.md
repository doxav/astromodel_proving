## Interpretation
1. The 0.9 mV RMSE cutoff is not currently reachable by these generation strategies. In the checked candidate pools, zero candidate rows reached mean trace RMSE <= 0.9 mV. Some rows reached feature >= 0.5, especially in adaptive runs, but none reached both mean-level proxies simultaneously.
2. Tight acceptance is therefore not just filtering noisy accepted candidates; it collapses acceptance to zero. The completed hardening variants show 0/12 accepted cells for both `nsga2_trace_feature_160_archive_tight_contract` and `nsga2_trace_feature_160_archive_tight_contract_adaptive_500`.
3. `nsga2_trace_feature_160_archive_adaptive_500` improves accepted candidate yield and effective-space breadth versus the fast trace+feature default, but it is much slower and still does not solve the visual/RMSE problem. In the focus run it reached 132 accepted rows and 10 cells with >=3 effective clusters, but mean best RMSE stayed near 3.95 mV.
4. `nsga2_trace_feature_160_archive_feature_focused` did not materially change results versus the baseline. This is expected with the current trace+feature multi-objective setup because changing scalar weights has limited effect on Pareto generation when the same objective dimensions are used.
5. Random/archive strategies remain useful for diversity-through-quantity, but they do not make the traces reviewer-ready by themselves. They produce far more candidates and strong effective-space spread, while median trace quality remains weak.
6. The best current use of these results is as a generation benchmark, not as evidence that the visual fit issue is fixed. The next code change should target the fit space/objective itself: wider `K_bath_middle`, per-sweep epsilon wiggle, additional formerly-free parameters from AFT uncut, and a trace objective that penalizes visually absurd shape mismatches more directly.

## Recommendation
- Keep `nsga2_trace_feature_160_archive` as the fast default only for screening and continuity with the current Step 04 notebook default.
- Use `nsga2_trace_feature_160_archive_adaptive_500` as the quality/diversity second pass when a cell has too few accepted candidates, but do not claim it reaches the desired visual contract.
- Do not make 0.9 mV / 0.5 the production acceptance rule yet. Keep it as a diagnostic target until the optimizer/model can actually generate candidates in that range.
- For reviewer-facing fitting maturity, the priority is now parameter-space/objective redesign, then rerun the same benchmark matrix.
